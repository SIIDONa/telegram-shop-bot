# Verify a release download

Every release includes `checksums.txt` with the SHA-256 hash of each Windows
ZIP and Linux tar archive. The hashes are also shown in release notes from
v3.0.1 onward. Verify the compressed archive before extracting or running it.

Download both the archive and `checksums.txt` from the **same version** on the
[official releases page](https://github.com/JumpCodeFrog/telegram-shop-bot/releases).
Save them in one folder. GitHub's automatically generated source-code archives
are not the executable downloads covered by this manifest.

SHA-256 verifies file integrity against the published hash. It is **not an author
signature**, Windows Authenticode signing, or a way to remove SmartScreen prompts.
If someone replaces both the archive and its published hash, this comparison
alone cannot detect that replacement.

## Windows PowerShell

Open PowerShell in the download folder. Change the filename below to match the
version and architecture you downloaded (`amd64` for Intel/AMD; `arm64` for ARM).
The example uses the v3.0.1 archive name.

```powershell
$archive = 'telegram-shop-bot_3.0.1_windows_amd64.zip'
$pattern = '^[a-fA-F0-9]{64}  ' + [regex]::Escape($archive) + '$'
$records = @(Get-Content -LiteralPath '.\checksums.txt' -ErrorAction Stop | Where-Object { $_ -match $pattern })
if ($records.Count -ne 1) { throw 'Expected exactly one checksum for this archive; check the version and filename.' }
$expected = ($records[0] -split '  ', 2)[0]
$actual = (Get-FileHash -LiteralPath $archive -Algorithm SHA256 -ErrorAction Stop).Hash
if ($actual -ne $expected) { throw 'SHA-256 mismatch. Do not extract or run this archive.' }
'SHA-256 OK'
```

Continue only after `SHA-256 OK`. Comparison ignores letter case. This uses
Windows' built-in [Get-FileHash](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash), so no additional utility is needed.

For a manual comparison, run `Get-FileHash -LiteralPath $archive -Algorithm SHA256`
and compare all 64 characters with the hash beside that exact filename in the
release notes or `checksums.txt`.

## Linux

Run this from the folder containing the downloaded archive and `checksums.txt`:

```bash
sha256sum --check --ignore-missing checksums.txt
```

The archive you downloaded must appear with `OK`, and the command must succeed.
`--ignore-missing` allows the other platform archives in the manifest to be absent.
If none of the listed files are present, verification fails.

## If verification fails

Check that the archive and manifest belong to the same release and that the
archive has its original filename. Download them again from the official release
page. If the hashes still differ, stop and report the release version and archive
filename in a [GitHub issue](https://github.com/JumpCodeFrog/telegram-shop-bot/issues).

After a successful check, continue with [Getting Started](getting-started.md).

The release manifest is generated by [GoReleaser's checksum step](https://goreleaser.com/customization/package/checksum/) using `algorithm: sha256`.
